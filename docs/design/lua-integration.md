# Lua連携の設計

[目次に戻る](../index.md)

[Lua設定と公開API](../features/lua.md)の公開APIを提供します。
Luaの組み込みには `mlua` の `lua54` と `vendored` を使います。

## 責務と依存関係

| 対象 | 責務 |
|---|---|
| RustのLua連携層 | `init.lua` の読み込み、公開APIとコールバックの実行、ハンドルの検証 |
| Rustの閲覧・UI基盤 | リンクの解釈とパス解決、文書と履歴の管理、キー入力の振り分け、フロートの描画とスクロール |
| Rustの受信基盤 | ループバック限定のソケットと、上限付きの非ブロッキング受信 |
| Rustのプロセス基盤 | 汎用の同期実行、起動エラーと終了結果の区別 |

`main` がLua連携層と閲覧・UI基盤を組み合わせます。`mlua` の型は連携層に閉じ込め、`app` やMarkdown adapterはLuaに依存しません。リンク抽出はMarkdown adapter側に置き、LuaでMarkdownを再解釈しません。

## ローカル受信

`net` はソケットと行の組み立てだけを担当し、Luaや文書の型に依存しません。Luaランタイムがソケットとコールバックを所有し、`session` が端末の入力待ちに合わせてポーリングし、受信を許す画面状態を判断します。フレームの長さ、同時に扱う接続数、受信期限、1回の処理量には上限を設けます。コールバックはUIと同じスレッドで、受信状態の借用を解放してから呼び出します。受信内容の解釈は呼び出し元のLuaコードに任せます。

## 入力と状態管理

- [カラースキーム](../features/colorscheme.md)は Lua ランタイムに保持します。Lua 連携層で入力全体を検証してから置き換え、描画時に現在の配色を参照します。配色の変更では文書・画像・レイアウトを作り直しません。

- 既定操作とLuaのキーマップは、Rust側の同じ連続キー判定を使います。
- 本文ビューとフロートは別のハンドルで識別します。フロートは作成元のビューに紐づけ、フロートを閉じた後の操作で新しいフロートを変更できないようにします。
- リンクIDの検証・パス解決と、文書の読み込みは分離します。文書を開く処理は絶対パスを受け取ります。読み込みが成功してから文書と履歴を更新し、戻るときは画面幅に依存しない閲覧位置と検索状態を復元します。
- 元ファイル行への移動要求は呼び出し時の文書IDに結び付けます。`session` が描画時にその文書のレイアウトと本文領域を使って一度だけ適用し、別の文書には適用しません。
