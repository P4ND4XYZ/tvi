# Lua連携の設計

[目次に戻る](../index.md)

[Lua設定とプラグイン](../features/lua.md)の公開APIを提供し、[リンク一覧](../features/links.md)と[ファイルピッカー](../features/file-picker.md)をLuaで組み立てます。
Luaの組み込みには `mlua` の `lua54` と `vendored` を使い、既存のイベントループで実行します。

## 責務と依存関係

| 対象 | 責務 |
|---|---|
| RustのLua連携層 | `init.lua` の読み込み、公開APIとコールバックの実行、ハンドルの検証 |
| Rustの閲覧・UI基盤 | リンクの解釈とパス解決、文書と履歴の管理、キー入力の振り分け、フロートの描画とスクロール |
| Rustのプロセス基盤 | 汎用の同期実行、起動エラーと終了結果の区別 |
| Luaプラグイン | 外部コマンドの選択・引数・出力解釈、検索語、ファジー検索、候補の並び順・選択位置、表示文言 |

`main` がLua連携層と閲覧・UI基盤を組み合わせます。`mlua` の型は連携層に閉じ込め、`app` やMarkdown adapterはLuaに依存しません。リンク抽出はMarkdown adapter側に置き、LuaでMarkdownを再解釈しません。

## 入力と状態管理

- [カラースキーム](../features/colorscheme.md)は Lua ランタイムに保持します。Lua 連携層で入力全体を検証してから置き換え、描画時に現在の配色を参照します。配色の変更では文書・画像・レイアウトを作り直しません。

- 既定操作とLuaのキーマップは、Rust側の同じ連続キー判定を使います。ファイルピッカーは実行ファイルに同梱し、設定を読み込む前に登録します。利用者は同梱の `ff` を上書きできますが、既定操作や利用者が登録済みのキー列は上書きできません。フロートの入力と終了処理は通常のキーマップから分離します。
- 本文ビューとフロートは別のハンドルで識別します。フロートは作成元のビューに紐づけ、フロートを閉じた後の操作で新しいフロートを変更できないようにします。
- リンクIDの検証・パス解決と、文書の読み込みは分離します。リンク一覧は選択時にリンク先を解決し、絶対パスで文書を開く共通の処理に渡します。読み込みが成功してから文書と履歴を更新し、戻るときは画面幅に依存しない閲覧位置と検索状態を復元します。
