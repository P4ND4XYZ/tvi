# Mermaid表示の設計

[目次に戻る](../index.md)

[Mermaidの図](../features/markdown.md#mermaidの図)を表示するため、外部コマンドによる変換と既存の画像描画を分けます。元のMarkdownは保存し直しません。変換やキャッシュの失敗時に記録する項目は、[診断ログ](../features/diagnostic-log.md#出力するイベント)を参照してください。

## 変換と画像描画の境界

- Markdown adapterはコードフェンスをパーサーで判定し、対象ブロックの位置とソースを取得します。文字列検索では判定しないため、他言語のコードブロックに含まれるフェンスの例は拾いません。
- 文書を開く経路は、`PATH` 上に `mmdc` があることを確認してから、Mermaidの変換処理にキャッシュの確認と変換を同期的に任せます。起動オプションはtviが管理し、Markdownから指定できないようにします。
- 変換で生成したPNGもキャッシュ済みのPNGも、同じバイト列を検証と保存に使い、通常の画像と共通の検証上限を適用します。検証できた画像を元のブロックの位置に渡し、既存の画像レイアウトで描画します。生成先をMarkdownの画像リンクとして埋め込まないので、文書を基準とする既存の相対パス解決に影響しません。変換できなかったブロックはコードとして描画・検索します。
- 変換にはOSの一時ディレクトリ内に用意した専用フォルダを使い、入力の `.mmd` と出力の `.png` を置きます。タイムアウト時は子プロセスを終了させ、変換作業が終わった時点で一時ファイルを片付けます。Unixでは期限前に協調終了を促し、期限に達したら元のプロセスグループを強制終了します。グループを離れ、協調終了にも応じない子孫プロセスの停止は保証しません。表示には読み込み済みの画像を使います。デコード済み画像は現在の表示だけで保持し、履歴には表示できた図の識別情報だけを残します。履歴から戻るとき、本文が変わっていなければ既存キャッシュだけを使い、再変換しません。本文が変わっていれば、文書を開くときと同じ経路で図を準備します。

## PNGキャッシュ

- ユーザーごとの永続キャッシュ領域（Windowsでは `%LOCALAPPDATA%\tvi\cache\mermaid\`）に、検証を通過したPNGだけを保存します。
- キーは `mmdc` に渡すソースと、テーマなど画像に影響する変換設定から計算したハッシュ値です。文書パスや更新日時には依存しないため、図以外の編集やブロックの移動ではキャッシュを再利用できます。不正なキャッシュは再変換します。
- 容量管理はMermaidのキャッシュ管理処理が担当します。[上限](../features/markdown.md#mermaidの図)を超える見込みなら、新しいPNGの保存直前に、生成日時の古いPNGから必要な分だけ削除します。起動時・終了時や読み込み時には削除しません。空きを確保できなくても画像表示は続け、キャッシュへの保存だけを見送ります。
