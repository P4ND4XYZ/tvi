# Markdown表示

[目次に戻る](../index.md)

## 概要

起動時に指定した単一のMarkdownファイルを、端末上で読みやすく表示する機能です。
文書は閲覧専用で、内容の編集や保存は行いません。

## 基本の使い方

```sh
tvi README.md
```

入力ファイルの文字コードはUTF-8とします。

見出し、段落、リスト、引用、コードブロックなどを、Markdownの装飾を反映して表示します。
本文は画面幅に合わせて折り返します。
表が本文の幅を超える場合は、罫線と各列の最小幅が収まる範囲で、列を揃えたままセル内を折り返します。
コードブロックでは、描画ライブラリが対応する言語のシンタックスハイライトを利用します。

画面下部の状態表示については、[状態表示とヘルプ](status-help.md)を参照してください。

## 起動時のエラー

起動に失敗した場合は、標準エラー出力に理由を表示し、非ゼロの終了コードで終了します。

## 自動再読み込み

外部のエディターなどで閲覧中の文書を上書きまたは置き換えると、キー操作なしで表示を更新します。同じ内容の保存や、別のファイルへの変更だけでは表示を更新しません。画像単体やLua設定の変更は監視しません。

- 更新時は閲覧位置をできるだけ近くに保ち、検索語とハイライトの有無を引き継いで一致箇所を計算し直します。リンクと画像の表示情報も更新し、閲覧履歴は増やしません。
- ヘルプ、コマンド・検索の入力欄、Luaのフロートを開いている間は、閉じてNORMALモードに戻るまで更新を保留します。
- ファイルが削除された場合や、通常ファイルとして読み取れない場合、UTF-8でない場合は、直前の表示を維持します。短い間隔で数回試しても読めなければ状態欄で一度通知し、次の変更通知で再読み込みを試みます。監視できない場合も一度通知し、閲覧を続けます。監視中の親フォルダーを削除して作り直した場合は、文書を開き直してください。通常の更新に通知はありません。
- ファイルの変更通知を利用するため、エディターの書き込み完了までは保証しません。

## 本文中の画像

画像を表示するには、次のように画像1枚だけを独立した段落に置きます。

```markdown
![構成図](./images/diagram.png)
```

- 実データがPNGまたはJPEGの通常ファイルが対象です。
- Kitty Graphics Protocolの対応はWindowsのみです。

## Mermaidの図

本文に独立して置かれた `mermaid` コードフェンスを、元のブロックの位置に図として表示します。引用やリスト内のブロック、ほかのコードブロックに書かれたフェンスの例は、コードのまま表示します。外部画像などの素材に依存する図は対象外です。

- 起動時、[リンク先への移動](links.md)、または自動再読み込みで本文が変わったとき、`PATH` に `mmdc` があれば、キャッシュにない図をPNGに変換します。成功して正常に読み込めた画像だけを表示し、元のMarkdownは書き換えません。
- 変換の時間予算は1図につき5秒、1文書につき15秒です。文書の予算が尽きたら後続の図は変換しません。ファイル入出力・画像のデコード・子プロセスの終了待ちは強制中断できないため、実際の待ち時間は予算を超えることがあります。結果を確定してから表示し、スクロール・リサイズ・本文に変更がない[履歴からの復帰](links.md)では再変換しません。変更のない文書へ戻る場合は、以前画像で表示した図だけを、`mmdc` が見つかり有効なPNGキャッシュを画像の上限内で読み込めるときに表示します。それ以外はコードのまま表示し、キャッシュへ書き込みません。
- `mmdc` が見つからなければ、キャッシュがあっても使わず、通知せずにコードを表示します。変換に失敗した図、制限時間内に変換できなかった図、PNGを読み込めなかった図は、それぞれ元のコードのまま表示します。失敗した図の件数は、状態欄に表示できるときに文書を開く操作につき一度通知します。原因の調査には[診断ログ](diagnostic-log.md)を参照してください。画像非対応の端末では変換もキャッシュの読み込みもせず、コードを表示します。
- PNGのキャッシュはtviの終了後も保持し、`mmdc` が見つからない場合も削除しません。次に文書を開いたとき、図のソースや変換設定が変わっていなければ再利用します。キャッシュ全体の上限はユーザーごとに128 MiBで、設定では変更できません。新規保存時に必要なら古いPNGを削除し、保存できなくても検証済みの図は表示します。保存先はWindowsでは `%LOCALAPPDATA%\tvi\cache\mermaid`、Linuxでは `$XDG_CACHE_HOME/tvi/cache/mermaid`（未設定・空・相対パスの場合は `$HOME/.cache/tvi/cache/mermaid`）です。絶対パスの保存先が得られなければキャッシュは使いません。
- 生成した図と通常画像は同じ画像サイズ上限と表示方式を使います。入力は1枚あたり16 MiB、各辺4096画素、総画素数は4 Mi画素までです。デコードした画像の文書予算は合計64 MiBで、通常画像を優先します。

画像にしたブロックのソースと、コードのまま表示したブロックの検索上の扱いは、[装飾・折り返しとの関係](search.md#装飾折り返しとの関係)を参照してください。

### 受け入れ条件

- 通常画像と、変換できる図・できない図が混在しても、各画像を正しい位置に表示し、失敗した図だけコードで読めます。元のファイルは変わりません。
- tviを再起動すると未変更の図を再利用し、図のソースを編集して開き直すとその図だけを再変換します。`PATH` から `mmdc` を外すとキャッシュがあってもコード表示になります。
